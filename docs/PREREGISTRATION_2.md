**CST Anti-UAV test split을 "한 번도 보지 않은 최종 시험"으로 동결한다.**

- 이미지와 라벨은 git에 넣지 않는다. 실패 사례 이미지와 데모에도 쓰지 않는다(재배포 조건을 피하기 위해 수치만 공개).

## 4. 공통 정의

- **기준 좌표**: 640×512. Svanström(320×256)의 크기·거리 수치는 2배 확대한 좌표로 적는다.
- **recall**: 드론 GT 박스 중 IoU ≥ 0.5로 매칭된 비율(1단계와 같은 탐욕 매칭).
- **프레임 오경보율(FAR)**: Svanström에서는 새·비행기·헬기 영상의 모든 프레임 중 출력이 하나라도 있는 프레임의 비율(세 클래스를 합쳐서 계산, 클래스별 값도 함께 보고). Anti-UAV에서는 드론 없는 프레임 기준.
- **오경보율을 맞춘 recall**: dev의 비드론 프레임에서 FAR이 목표값 이하가 되는 가장 낮은 임계값을 고르고, 그 임계값을 test에 그대로 적용한다. test에서는 recall과 실제 FAR을 함께 보고한다.
  - 목표 **T_base** = S1이 임계값 0.954, 배율 ×2로 dev 비드론 프레임에서 내는 FAR(주 지표. "오경보를 1단계만큼만 허용할 때 recall이 얼마나 늘었나").
  - 목표 **T10** = 10% (보조).
  - 학습이 없는 설정은 dev_a + dev_b로, dev_a를 학습에 쓴 모델은 dev_b로 임계값을 고른다.
- **구간**: 영상 단위 percentile bootstrap 95%(B=1000, seed 0). 두 구성의 비교는 같은 프레임에서 영상 단위로 짝지은 차이의 bootstrap 구간으로 한다.
- **추론 기본값(S1 구성)**: Svanström ×2 확대, 전체 이미지 한 번, TTA 없음, 이미지당 최대 20개, 점수 0.001 이상 저장.

## 5. 질문별 지표, 예측, 판정 규칙

### Q1. 왜 떨어졌나 (새 학습 없음, S1)

자료: Anti-UAV test의 S1 캐시 예측(설명용)과 Svanström dev. 같은 분해를 최종 평가 때 Svanström test에서 한 번 더 계산해 함께 싣는다.

기술 지표(판정 없음): Svanström AP@0.5(드론 영상만 / 비드론 프레임을 포함한 전체), 두 데이터셋의 정탐 점수 분포, FAR 대 recall 곡선, IoU 0.5 / 0.3 / 0.1과 중심 거리 기준(검출 중심이 GT 박스 안) recall, 놓친 GT의 최대 IoU 분포, 느슨하게 매칭된 쌍의 예측 박스 / GT 박스 크기 비, 같은 크기 구간(기준 좌표 <8, 8–12, 12–16, 16–24, 24–32, 32–48, 48–64, ≥64 px)의 recall.

**분해 규칙.** G = R_AU − R_SV (임계값 0.954, IoU 0.5). 요인 하나만 바꿨을 때 줄어드는 G를 그 요인의 몫으로 한다.

| 요인 | 바꾸는 것 | 몫 |
|---|---|---|
| T 임계값 | 두 데이터셋 모두 점수 ≥ 0.05로 평가 | G − G_T |
| L 박스 위치 기준 | 두 데이터셋 모두 IoU ≥ 0.1로 평가 | G − G_L |
| S 표적 크기 분포 | Anti-UAV의 크기 구간별 recall을 Svanström의 크기 분포로 가중 평균(Anti-UAV 박스가 30개 미만인 구간은 바로 위 구간과 합침) | R_AU − R_AU^std |
| 설명되지 않는 몫 | T, L, S를 모두 적용한 뒤에도 남는 차이 G_TLS | G_TLS |
| 겹치는 몫 | (T + L + S 몫의 합) − (G − G_TLS) | |

- 판정: 몫이 5 %p 이상이고 bootstrap 95% 구간이 0을 포함하지 않으면 "주요 요인"이라고 적는다. 설명되지 않는 몫이 G의 절반을 넘으면 "크기·임계값·위치 기준으로는 절반도 설명되지 않는다"고 적는다.
- 임계값의 다른 정의(두 데이터셋의 FAR을 3.5%로 맞춤)로 계산한 값도 함께 싣는다. 이 정의에서는 임계값 몫이 음수일 수 있다.

입력 실험(dev 영상, 10프레임마다 1장): 전체 이미지 ×1, ×2, ×3, ×4와 타일 추론 2종(×3과 ×4로 확대한 뒤 2×2 타일, 타일 겹침 20%, NMS IoU 0.5로 합침). 1280×1024 추론이 메모리 부족으로 죽거나 장당 1.5초를 넘으면 실패로 기록하고 그 설정은 뺀다.

오경보 분석(dev 비드론 영상, 임계값 0.954): 오경보 박스의 위치(화면 격자), 크기, 점수, 라벨된 물체와의 관계(중심이 물체 박스를 1.5배 키운 영역 안인지), 화면 가장자리·글자 영역 여부. 실패 사례 이미지는 S1으로 dev 영상에서 다시 만든다.

**예측 (Claude):**

| | 예측값 (범위) |
|---|---|
| P1. Svanström dev 드론 영상 AP@0.5 | 0.55 (0.48–0.62) |
| P2. 점수 ≥ 0.05, IoU 0.5 recall: Svanström dev / Anti-UAV test | 66% (60–72) / 92% (90–95) |

### Q2. 학습 없이 얼마나 되찾나

후보는 모두 dev에서 고른다. 선택 지표는 dev의 iso-FAR(T_base) recall이다.
1. **임계값 보정**: T_base와 T10에 맞춘 임계값.
2. **배율·타일**: Q1 입력 실험에서 iso-FAR recall이 가장 높은 설정. 1 %p 안의 차이면 계산이 싼 쪽.
3. **TTA**: 좌우 반전. 두 결과를 합쳐 NMS(IoU 0.5), 남은 박스의 점수는 두 추론 점수의 평균(한쪽에만 있으면 그쪽 점수의 절반). dev iso-FAR recall이 1.0 %p 이상 늘 때만 채택(계산 2배).
4. **추적**: 낮은 임계값의 검출을 이미지 평면에서 추적한다.
   - 상태 [x, y, vx, vy](박스 중심, 기준 좌표), 등속 Kalman filter, chi-square gating(2자유도), Hungarian 전역 최근접 연관(확정 항적 먼저), M-of-N 확정, K번 연속 미검출 시 삭제. 설계는 `projects/radar-track-lab`(브랜치 hyh4867/Radar, c4ed4d7)의 `tracker.py`를 따르되 코드는 이 프로젝트에 새로 쓴다.
   - **먼저 재는 것**: dev의 GT 중심 궤적으로 등속 예측 잔차와 정지 가정 잔차를 추적 주기(6 Hz)에서 비교한다. 프레임 간 전역 이동(phase correlation)도 재서 표적의 겉보기 움직임 중 카메라 움직임의 몫을 본다. Anti-UAV val에서도 같은 값을 잰다.
   - 규칙: 등속 모델의 잔차 중앙값이 정지 모델보다 작으면 등속 모델을 쓰고, 아니면 random-walk 모델을 쓴다. 전역 이동 보정은 등속 잔차 중앙값을 20% 이상 줄일 때만 넣는다.
   - dev에서 고르는 값: 낮은 임계값 {0.05, 0.1, 0.2, 0.3, 0.5}, (M, N) {(2,3), (3,4), (3,5), (4,6)}, K {2, 3, 5}, 과정 잡음(잔차 측정값에서 정한 3개 수준), 미검출 프레임에 예측 박스를 출력하는 횟수 {0, 1, 2}. 출력 여부를 정하는 연속 값은 항적 점수(항적에 붙은 검출 점수의 평균)이고, 이 값의 임계값으로 FAR을 맞춘다.
   - 지표: iso-FAR recall(확정 항적의 출력 박스 기준), 비드론 영상의 분당 가짜 확정 항적 수, 드론 영상에서 첫 GT 프레임부터 첫 정탐 확정까지의 시간(끝까지 확정 못 한 영상의 비율 따로), 확정 뒤 항적 유지율(GT 프레임 중 정탐 출력이 있는 비율), GT에 붙은 항적 ID 수.
   - 추적 주기: Svanström 6 Hz(5프레임마다). 전 프레임 추론은 계산 한도 때문에 하지 않는다.
- 판정: test에서 S1 대비 짝 비교한 iso-FAR recall 차이의 95% 구간이 0보다 위면 "되찾았다"고 적고, 되찾은 양은 %p와 "차이의 몇 %"(차이 = Anti-UAV test recall 84.9% − 같은 test 영상에서의 S1 recall)로 적는다. 구간이 0을 포함하면 "차이를 확인하지 못했다", 0보다 아래면 "나빠졌다"고 적는다.

### Q3. 학습으로 얼마나 되찾나

- 학습 실행은 **최대 4회**(R1 1회, R2 3회). 100 iteration을 넘긴 실행은 중간에 죽어도 1회로 센다. 순서는 R1 → R2(N 작은 것부터).
- 실행당 한도: **벽시계 150분**(epoch별 검증 포함). 넘으면 마지막 체크포인트에서 멈추고 그대로 보고한다.
- 공통 설정: `configs/full.yaml`의 저메모리 설정(worker 0, 2장 × 4 gradient accumulation, 유효 batch 8, 평가 batch 1), screen + `caffeinate -i`, epoch마다 체크포인트, seed 0, 시작 가중치는 S1.
- **R1 (작은 표적 증강, Svanström 자료 없음)**: Anti-UAV train만으로 2 epoch(2,150 iteration), lr 0.005 cosine, warmup 100. 기존 증강에 더해 표본의 50%에 작은 표적 증강을 건다. (a) 표적 크기 sqrt(w·h)가 4–12 px 균등분포가 되도록 축소. (b) 그중 절반은 저해상도 센서 흉내: 최종 크기의 1/k(k ∈ {2, 3, 4})로 줄였다가 bilinear로 k배 확대(blur)하고 Gaussian noise(σ 0–4 계조)를 더한다.
  체크포인트 선택: dev_b iso-FAR recall이 높은 epoch. 단 Anti-UAV val AP@0.5가 S1(0.937)보다 0.02 넘게 떨어진 epoch은 제외.
- **R2 (대상 도메인 소량 미세조정)**: 시작 가중치는 S1과 R1 중 dev_b iso-FAR recall이 높은 쪽. batch 8장 중 6장은 Anti-UAV train, 2장은 Svanström dev_a 프레임(Q2에서 고른 배율로 확대한 뒤 320×320 crop). 1,075 iteration, lr 0.005 cosine.
  dev_a 드론 영상 수 N = 4, 12, 37(전부). 비드론 dev_a 영상은 N에 비례해(N × 49/37, 반올림) 음성으로 넣는다(새·비행기·헬기 박스는 라벨로 쓰지 않음). 영상은 고정 seed 순서로 앞에서부터 고른다.
  체크포인트: 마지막 iteration. Anti-UAV val AP@0.5와 Anti-UAV test 수치를 함께 보고한다.
- 중단 조건: 디스크 여유 5 GB 미만, 200 iteration 연속으로 iteration당 6초 초과(스왑 과다), 프로세스가 죽고 재개가 한 번 실패. 중단하면 그 지점까지의 결과로 보고한다.
- 판정: Q2와 같다(test, S1 대비 짝 비교, iso-FAR recall). R1과 R2는 같은 추론 구성(Q2에서 고른 것)으로 비교한다.
  퇴행 기준: Anti-UAV test에서 recall이 2.0 %p 넘게, AP@0.5가 0.02 넘게, 드론 없는 프레임 FAR이 2.0 %p 넘게 나빠지면 "퇴행"이라고 적는다.

## 6. 계산 계획과 한도

- 무거운 작업(학습, 추론)은 한 번에 하나만 돌린다. 시작 전에 `ps`로 다른 세션의 무거운 프로세스를 확인한다.
- 예상 추론 시간(1단계 측정값: 640×512 한 장 약 0.22초): 입력 실험 약 5시간, dev·test 재추론은 고른 배율에 따라 1.5–6시간, 모델당 최종 평가(Svanström test, Anti-UAV test, CST) 약 2.5시간.
- 추론 캐시는 `runs/stage2/`에 두고(git 제외), 수치는 `results/stage2/*.json`에 쓴다. 표와 그림은 JSON에서 자동 생성한다.

1. TTA 확인은 고른 배율(×1) 하나에서만, 입력 실험과 같은 프레임(dev의 절반)에서 했다. 등록 문서에는 어느 프레임에서 잴지 적지 않았다.
2. 640×512 자료(Anti-UAV, CST)에서도 A, B, C 구성은 TTA를 쓴다(배율 ×1). S1 기준값은 1단계 그대로 TTA 없이 낸다. Anti-UAV val의 F1 최대 임계값은 TTA를 켠 val 추론에서 모델마다 다시 구한다.
3. **A를 CST와 Anti-UAV 추적 표본에도 평가한다**(등록 문서에는 S1, B, C37만 있었다). B·C37과 S1의 차이에서 TTA의 몫과 학습의 몫을 나누기 위해서다. CST에서 한 번씩 추론하는 구성은 S1, A, B, C37이 된다.
4. 보정에 쓰는 dev: A와 B는 dev 전체(177 영상), C4·C12·C37은 dev_a를 학습에 썼으므로 dev_b(91 영상)만. T_base도 같은 프레임에서 S1의 FAR로 잡는다.
5. R2의 Svanström 학습 프레임은 고른 배율(×1) 그대로 넣는다.
6. 추적기 파라미터가 그리드 끝에서 골라져도(S1 ×2 검출에서 낮은 임계값 0.5, 예측 출력 0회) 그리드를 넓히지 않는다.

**계산 계획:** TTA로 추론 시간이 2배가 되어 test 쪽 추론이 약 22시간이다(Svanström test 모델당 약 54분, Anti-UAV test + 보충 약 73분, CST 약 132분, 추적 표본 약 66분). 순서는 Svanström test → Anti-UAV test → CST → Anti-UAV 추적 표본이고, 끝내지 못한 구성은 "실행 못 함"으로 적는다.
