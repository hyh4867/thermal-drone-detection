## 1. 질문

같은 자료와 설정에서 학습 seed만 바꾸면 T2-20의 이득(CST val)과 대가(Anti-UAV test, Svanström test)가 얼마나 달라지는가.

3단계는 설정마다 한 번(seed 0)만 학습했다. 이 실행은 그 한계를 seed 3개(0, 1, 2)까지 줄인다. seed 3개로는 seed 분포를 추정할 수 없다. 보고하는 것은 3개 값의 평균과 범위다.

## 2. 이미 본 것

- 3단계의 모든 결과. seed 0의 T2-20은 CST val AP@0.5 0.415 [0.314, 0.521], S1과의 차이 +0.335 [0.241, 0.433], tiny 구간 중심 기준 recall 47.0%. Anti-UAV test는 AP@0.5 0.885 → 0.863, 오경보율 3.5% → 6.9%로 J5 퇴행. Svanström test는 새·비행기·헬기 프레임 오경보율 39.3% → 73.3%, 중심 기준 recall +9.4 %p [5.5, 13.6].
- **세 시험 자료(CST val, Anti-UAV test, Svanström test)는 모두 3단계에서 이미 썼다.** 이 실행은 그 자료를 다시 쓴다. 처음 보는 시험이 아니다. 다만 여기서는 아무것도 고르지 않는다. 구성은 seed 0과 같고, seed별 임계값은 CST train의 선택용 시퀀스에서만 정하며, 시험 결과로 seed를 고르거나 버리지 않는다.
- 이 문서를 쓰기 전에 돌린 것(새 시험 정보 없음):
  - seed 0을 새 집계 코드로 다시 집계했다. 3단계 캐시와 동결 임계값을 읽기만 했고, 3단계 파일의 수치와 일치했다(비교한 값의 최대 차이 1e-12 이하).
  - 학습 인자 확인: seed 1로 3 iteration을 돌렸다. 가중치와 결과를 저장하지 않는 모드다.
  - 추론·캐시 확인·동결 경로 확인: seed 0의 가중치를 임시 이름으로 넣어 선택용 프레임 40장과 Svanström test 프레임 40장을 저장소 밖 임시 폴더에서 추론했다. seed 0의 같은 프레임 예측은 3단계 캐시에 이미 있다.

| 항목 | 값 |

| seed가 바꾸는 것 | Anti-UAV 프레임의 batch 순서, 증강 난수(축소, 자르기, 뒤집기, 잡음), batch마다 뽑는 CST 프레임, torch 난수. 시작 가중치와 자료는 같다 |

| 추론 | 3단계 추론 코드(`tdd.stage3.infer.run`)를 그대로 부른다. 전체 이미지 한 번, TTA와 타일 없음, 한 장씩. 추론 때의 seed는 3단계처럼 설정 파일의 0이다 |
| 박스 보정 | 없음(k = 1) |

- 학습이 1,075 iteration을 끝내지 못한 seed는 동결하지 않고 평가하지 않는다. 그 사실을 보고한다.
- seed를 더 돌리지 않는다. seed 1, 2 중 하나를 "대표"로 고르지 않는다. 3단계의 대표 수치(seed 0)는 그대로 둔다.
- 같은 seed를 두 번 학습해 비교하지 않는다. 그래서 seed 사이의 차이에는 MPS 연산의 비결정성이 있다면 그것도 섞여 있다. 둘을 나누지 않는다.

코드 변경은 덧붙이는 것뿐이다. 학습 스크립트에 출력 폴더를 바꾸는 `--group` 인자를 더했고(기본값이면 동작이 같다), 새 패키지 `src/tdd/seeds/`가 3단계 추론·평가 함수를 불러 쓴다. 가중치와 캐시는 `runs/seeds/`, 결과는 `results/seeds/`에 둔다.

## 4. 평가 (3단계와 같은 자료, 지표, bootstrap)

| 자료 | 내용 | 기준 |
|---|---|---|
| CST val (40 시퀀스, 11,335장) | AP@0.5, IoU 0.5·중심 기준 recall, tiny·small 구간 recall, 박스 없는 프레임의 오경보율. 시퀀스 단위 bootstrap(B = 1000, seed 0) | (S1, m = 1): 3단계 캐시 `s1_m1__cst_val`, 1단계 임계값 0.954 |
| Anti-UAV test (9,582장) + 보충 프레임 | AP@0.5, recall, 오경보율과 S1과의 짝 차이. 보충 프레임은 3단계처럼 크기 구간별 recall에만 쓴다 | 1단계 모델과 설정(1단계 캐시), 3단계와 같다 |
| Svanström test 5,819장 (`svan_test_h`, 3단계 추가 6과 같은 표본) | 새·비행기·헬기 프레임의 오경보율, 중심 기준·IoU 0.5 recall, 영상 단위 bootstrap(B = 1000, seed 0) | (S1, m = 1): 3단계 캐시 `s1_m1__svan_test_h` |

S1은 다시 추론하지 않는다. seed 0도 다시 추론하지 않고 3단계 캐시와 동결 임계값으로 같은 코드에 넣어 집계한다.

### seed별 판정 (3단계 규칙 그대로)

- **J4.** CST val AP@0.5의 짝 차이(T2-20 seed k − S1)의 95% 구간 하한이 0보다 크면 "도움이 됐다". AP@0.5가 0.30 미만이면 "여전히 낮다"를 함께 적는다. (3단계의 J4는 트랙 1 최종 구성과의 차이였고, 그 구성이 (S1, m = 1)이었다.)
- **J5.** Anti-UAV test에서 1단계 모델·설정과의 차이가 recall(IoU 0.5) −2 %p, AP@0.5 −0.02보다 나쁘거나 오경보율이 +2 %p보다 크면 "퇴행". 어느 항목이 한도를 넘었는지 함께 적는다.
- Svanström은 판정이 없다. 3단계 추가 6의 해석 규칙(중심 기준 recall 짝 차이의 구간)을 seed마다 그대로 적는다.

## 5. 보고

- seed별 값(0, 1, 2)과, seed 0을 포함한 3 seed의 평균, 최솟값, 최댓값, 범위(최대 − 최소), 표본 표준편차. seed 수가 3이라 seed 분포의 구간은 내지 않는다.
- seed별 J4, J5 판정과 한도를 넘은 항목.
- 설명용: CST val에서 seed 1, 2 각각과 seed 0의 짝 차이(같은 시퀀스 bootstrap, 각자 자기 임계값).
- 읽는 규칙(미리 고정):
  - 판정: 세 seed의 J4가 같고 J5가 같으면 "판정은 seed에 따라 바뀌지 않았다", 아니면 어느 판정이 바뀌었는지 적는다.
  - 크기: CST val AP@0.5의 3 seed 범위가 0.10 이하이면 "seed 차이는 시험 자료를 다시 뽑을 때의 불확실성보다 작다"고 적는다. 0.10은 seed 0의 bootstrap 95% 구간 반폭(약 0.10)이다. 넘으면 "seed 차이가 그 불확실성만큼 크다"고 적는다.
- 예상과 다르게 나와도 그대로 보고한다. 끝나지 않은 부분은 "실행하지 않음"으로 적는다.

## 7. 보호 장치와 검증

1. **동결 뒤에만 시험 추론.** seed k의 동결 파일 `results/seeds/frozen_seed<k>.json`(임계값, 체크포인트 sha256)이 **커밋되기 전에는** CST val, Anti-UAV test, 보충 프레임, Svanström test 추론을 코드가 거부한다. 3단계는 파일이 있는지만 봤고, 여기서는 git에 커밋됐고 그 뒤 바뀌지 않았는지를 본다. 체크포인트의 sha256이 동결값과 다르면 거부한다. 동결 파일은 seed마다 한 번만 쓴다.
2. **깨끗한 작업 트리에서만 집계.** 집계는 `git_dirty`가 false일 때만 돈다.
3. **캐시 확인(3단계 방식).** 캐시마다 meta와 체크포인트 sha256, 실행 로그의 DONE 줄, 줄 수와 형식, 프레임 5장의 재추론(위 5개 점수의 평균 절대 차이 < 0.01, 같은 프레임의 다른 캐시보다 가까울 것)을 본다. 다른 캐시에는 seed 0과 S1의 3단계 캐시, 다른 seed의 캐시가 들어간다. 선택용 캐시는 동결 전에, 시험 캐시는 집계 전에 확인한다. 통과하지 못하면 집계하지 않는다.
4. **독립 재계산.** `scripts/independent_check_seeds.py`(표준 라이브러리만, tdd 패키지를 쓰지 않음)로 seed마다 CST val의 AP@0.5와 recall, Anti-UAV의 AP@0.5·recall·오경보율과 J5 항목, Svanström의 recall과 오경보율, 그리고 3 seed 평균·범위를 다시 계산해 비교한다(허용 오차 1e-6).
5. **seed 0 재현.** seed 0을 같은 집계 코드에 넣은 값이 3단계 파일과 일치해야 집계가 진행된다.
6. pytest 전체를 돌려 전체 출력과 통과 개수를 보고한다.

## 8. 순서와 실행 규칙

- 순서: seed 1 학습 → 선택용 추론 → 캐시 확인 → 임계값 동결 → 동결 파일 커밋 → CST val → Anti-UAV test(+ 보충) → Svanström test → 캐시 확인 → 집계. 그다음 seed 2를 같은 순서로. 마지막에 seed 0 집계, 3 seed 요약, 독립 재계산. `scripts/seeds_run.sh`가 seed 1, 2를 자동으로 돌리고 동결 파일과 seed별 결과를 커밋·push한다.
- 예상 시간(seed 0의 기록): 학습 43분, 선택용 추론 21분, CST val 43분, Anti-UAV 42분, Svanström 22분. seed 하나에 약 2시간 50분.
- GPU 작업은 한 번에 하나다. 작업마다 시작 전에 스왑과 메모리를 기록하고, 스왑 사용이 3 GB를 넘거나 여유 메모리가 10% 미만이면 5분씩 기다린다. 잠금(heavy-run)은 쓰지 않는다(이번 실행에 대한 사용자 지시). 다른 세션의 프로세스는 건드리지 않는다. screen과 caffeinate -i로 돌린다. 학습은 250 iteration마다, 추론 캐시는 줄 단위로 이어서 다시 시작할 수 있다.
- 시간 한도(KST): seed 2 학습은 2026-11-24 02:30 전에만 시작한다. 04:30 이후에는 새 긴 실행(학습, 추론)을 시작하지 않는다. 06:00까지 보고서를 push한다. 끝나지 않은 부분은 거기까지를 보고한다.

## 9. 지시를 해석한 점

- **"ASTRA 세션이 끝난 뒤 시작."** 이 문서를 쓰는 시점(2026-11-23 20시대)에 ASTRA 작업 폴더의 마지막 커밋은 18:12이고 보고서가 push돼 있으며, 그 뒤 바뀐 파일이 없고, python 프로세스(GPU 작업)가 하나도 돌고 있지 않았다. 이것을 "끝났다"로 읽었다. 학습을 시작하기 직전에 다시 확인하고, ASTRA의 GPU 작업이 돌고 있으면 끝날 때까지 기다린다.
- **"보충 프레임 포함."** 3단계와 같은 뜻으로 읽었다. Anti-UAV test 9,582장이 J5의 대상이고, 보충 프레임(작은 표적)은 따로 추론해 크기 구간별 recall에만 더한다.
- **"seed별 J4·J5 판정."** J4의 기준은 (S1, m = 1)이다(4절).
- **"시험 추론" 전의 동결.** CST val뿐 아니라 Anti-UAV test와 Svanström test 추론도 동결 파일 커밋 뒤에만 돌게 했다.
- **selection용 S1 추론, m = 2 추론은 반복하지 않는다.** seed와 무관하거나(S1) 고정했기(m) 때문이다.
